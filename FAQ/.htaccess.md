# What is Server:

1. Server ek aisa powerful computer hota hai jo clients ka data, files images ya sub store karta hai apne pass.

2. Jab bhi koi user ya koi bhi client kisi cheez ki request karta hai, to server us request ko sunta hai, samajhta hai, aur process karta hai.

3. Phir server us client ko sahi jawab (response) bhej deta hai — jaise webpage, image, video, ya data jo client ki request ki oiske according.

4. Ye poora kaam network (internet) ke zariye hota hai, aur server 24/7 chalta rehta hai — kabhi band nahi hota.

# Type of Servers:

## This is the Type 1 **Servers**:

1. **Hardware Server**: Ye batata hai ke server dikhne mein means physically dekhne mein kaisa hote hai or kahan rakha hote hai.
2. isme **CPU**,**RAM**,**Hard Disk**,**Motherboard**,**Power Supply** yeah sub hota hai.
   - **Tower Server**: Aap ke normal computer jaisa **desktop**
   - **Rack Server**: yeah mostly data centers mein hote hai aik rack mein 10 to 40 server ate hai
   - **Blade Server**: Ek rack mein 100+ server a sekhte hai.
   - **Mainframe Server**: Laakhon requests ek saath handle karta hai
   - **Cloud Server**: Asli mein koi box nahi — ye ek virtual server hai like **AWS**, **Google** **Cloud**, **Azure**

## This is the Type 2 **Servers**:

1. **Service type Server**: Ye batata hai ke server actual mein kam kia karta hai yeah actual mein aik Programe hote hai jo Hardware server ka andar run hote hai.
   - **Web Server**: Websites serve karna — HTML, CSS, images, video , audio bhejna
   - **Database Server**: Data ko store karna aur retrieve karna MySQL, PostgreSQL, MongoDB, Oracle.
   - **File Server**: Files store karna aur share karna — documents, photos, videos.
   - **Mail Server**: Emails bhejna, receive karna, store karna
   - **DNS Server**: Domain name (jaise google.com) ko IP address (142.250.190.46) mein badalna BIND, Google DNS (8.8.8.8), Cloudflare DNS
   - **FTP Server**: Files upload aur download karna — vsftpd, FileZilla Server

# `.htaccess`

1. `.htaccess` is **"Hypertext Access"**. Ye ek **configuration file** hai jo **Apache web server** par chalti hai.
   - Iska naam `.` se start hota hai — is liye ye **hidden file** hoti hai
   - Ye **per-folder** hoti hai — jis folder mein rakho, sirf us folder aur uske andar ke folders par asar karti hai
   - Ismein likha code **Apache server** padhta hai har request par
   - Agar aap ka server **Nginx** hai, to `.htaccess` kaam nahi karegi (Nginx mein alag config hoti hai yeah Apache web server per run hoti hai)

---

## Ye kaam kaise karti hai? (Basic flow)

Jab koi user browser mein URL daalta hai:

```
http://infosphere.42web.io/about
```

1. Request Apache server tak pahunchti hai
2. Apache dekhta hai — "is folder mein `.htaccess` hai kya?"
3. Agar hai, to uske rules padhta hai
4. Rules ke mutabiq decide karta hai — redirect karna hai? block karna hai? kisi aur file par bhejna hai?
5. Phir final jawab user ko bhejta hai

## `.htaccess` ke 5 bade kaam

### 1. **URL Rewriting** (sabse zyada use hota hai)

URL ko badalna ya chhupana. Jaise:

```apache
RewriteEngine On
RewriteRule ^about$ about.php [L]
```

**Matlab:** Jab koi `yoursite.com/about` khole, to actually `about.php` file chale, lekin URL bar mein `about` hi dikhe.

**Faida:** Aap ki URLs saaf aur sundar lagti hain. `about.php?id=5&cat=3` ki jagah `about/5/3` dikhta hai.

**Laravel mein yahi ho raha hai:**

```apache
RewriteRule ^ index.php [QSA,L]
```

Ye kehta hai — "jo bhi URL aaye, sab `index.php` par bhej do, Laravel khud handle kar lega."

---

### 2. **Redirects** (HTTPS, www, purane URLs)

```apache
# HTTP se HTTPS par bhejo
RewriteCond %{HTTPS} off
RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
```

**Matlab:** Jo bhi `http://` par aaye, usko `https://` par bhej do.

Aur examples:

```apache
# www se bina-www par
RewriteCond %{HTTP_HOST} ^www\.(.+)$ [NC]
RewriteRule ^ https://%1%{REQUEST_URI} [L,R=301]

# Purane URL se naye URL par
Redirect 301 /old-page.html /new-page.html
```

---

### 3. **Security** (files ko chhupana, block karna)

```apache
<Files .env>
Order allow,deny
Deny from all
</Files>
```

**Matlab:** `.env` file ko koi browser se nahi khol sakta. Agar koi `yoursite.com/.env` khole, to "403 Forbidden" milega.

Ye bohot zaroori hai kyunke `.env` mein database passwords hote hain. Agar ye public ho jaye to hacker aap ka database uda sakta hai.

Aur security examples:

```apache
# Directory listing band karo (folder ke andar ki files na dikhein)
Options -Indexes

# Sirf specific IP ko allow karo
Order deny,allow
Deny from all
Allow from 192.168.1.1

# Specific files block karo
<FilesMatch "\.(sql|log|ini|conf)$">
    Order allow,deny
    Deny from all
</FilesMatch>
```

---

### 4. **Error Pages** (custom error pages)

```apache
ErrorDocument 404 /404.php
ErrorDocument 500 /500.php
```

**Matlab:** Jab 404 error aaye, to default Apache wala boring page na dikhe, balke aap ka apna sundar `404.php` page dikhe.

---

### 5. **Performance** (caching, compression)

```apache
# Gzip compression on karo (site tez load hogi)
<IfModule mod_deflate.c>
    AddOutputFilterByType DEFLATE text/html text/css application/javascript
</IfModule>

# Browser caching
<IfModule mod_expires.c>
    ExpiresActive On
    ExpiresByType image/jpg "access plus 1 year"
    ExpiresByType text/css "access plus 1 month"
</IfModule>
```

**Matlab:** Images aur CSS files user ke browser mein save ho jayen, taake dobara visit par tez load ho.

## Real example — aap ki site ka flow

Aap ki site ka setup:

**Root `.htaccess`** (`htdocs/.htaccess`):

```apache
RewriteEngine On

# HTTPS par bhejo
RewriteCond %{HTTPS} off
RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]

# Sab kuch public/ mein bhejo
RewriteRule ^$ public/ [L]
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^(.*)$ public/$1 [L]

# .env hide karo
<Files .env>
Deny from all
</Files>
```

**Public `.htaccess`** (`htdocs/public/.htaccess`):

```apache
RewriteEngine On
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^ index.php [QSA,L]
```

### Ab samjho jab koi `http://infosphere.42web.io/blog` kholega:

1. **Request aayi** — `http://infosphere.42web.io/blog`
2. **Root `.htaccess` padhi gayi:**
   - Pehla rule: "HTTPS off hai? Haan. To `https://...` par bhejo" → redirect
3. **Browser dobara request bhejta hai** — `https://infosphere.42web.io/blog`
4. **Root `.htaccess` phir chali:**
   - HTTPS check: ab on hai, skip
   - `public/` mein bhejo: `/blog` → `public/blog`
   - Lekin `public/blog` naam ki koi file nahi
5. **`public/.htaccess` chali:**
   - `blog` na file hai na folder
   - To `index.php` par bhejo
6. **Laravel ka `index.php` chala:**
   - Routes dekhe, `blog` ka controller chalaya
   - HTML page banaya
7. **User ko page mila** — URL bar mein `https://infosphere.42web.io/blog`

## `.htaccess` ke important symbols samjho

| Symbol     | Matlab                                              |
| ---------- | --------------------------------------------------- |
| `^`        | Line ki shuruaat                                    |
| `$`        | Line ka aakhir                                      |
| `.*`       | Kuch bhi (zero ya zyada characters)                 |
| `(.*)`     | Kuch bhi, capture karo                              |
| `$1`, `$2` | Captured cheezein wapas use karo                    |
| `[L]`      | Last rule — iske baad ruk jao                       |
| `[R=301]`  | Permanent redirect                                  |
| `[R=302]`  | Temporary redirect                                  |
| `[NC]`     | No Case (case insensitive)                          |
| `[QSA]`    | Query String Append — `?id=5` waghera preserve karo |
| `!`        | NOT (matlab "nahi")                                 |
| `-f`       | File exist karti hai                                |
| `-d`       | Directory exist karti hai                           |

## Zaroori baatein yaad rakho

1. **Ek chhoti si ghalti poori site todh sakti hai.** Hamesha backup rakho.
2. **Comment ke liye `#` use karo** — `# ye comment hai`
3. **`.htaccess` mein typo** = "500 Internal Server Error"
4. **Sirf Apache par chalti hai.** Nginx, IIS, ya kuch aur server par kaam nahi karegi.
5. **Performance thodi slow hoti hai** kyunke Apache har request par file padhta hai. Isi liye bade sites Nginx use karte hain.
6. **Sensitive info na rakho** — `.htaccess` khud public ho sakti hai kabhi kabhi (rare), is liye passwords na likho.
7. **Cache clear karna zaroori** — `.htaccess` change karne ke baad browser cache clear karo.

## Aasan example — ghar ki tarah samjho

Socho aap ka ghar hai (website). `.htaccess` aap ka **chowkidar** hai:

- Koi aaye to **check karta hai** — HTTPS hai ya nahi?
- **Bhejta hai** sahi darwaze par (redirect)
- **Rokta hai** ghalat logon ko (security)
- **Batata hai** rasta (URL rewriting)
- **Dikhata hai** sundar error page (custom errors)

Chowkidar ke bina bhi ghar chalta hai, lekin phir har koi andar aa sakta hai, ghalat kamre mein ja sakta hai, aur ghar ki koi izzat nahi rehti.
